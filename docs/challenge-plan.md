# WebMCP Challenge plan

## Deadline

Official submission deadline: September 3, 2026 at 1:00 p.m. PDT, which is September 4, 2026 at 1:30 a.m. IST.

Internal target: complete the production build and repository by the evening of September 2 IST. Reserve the final day for verification, recording, upload, and Devpost submission.

## Judging alignment

### WebMCP leverage

Demonstrate semantic tools that read and mutate shared planning state, return evidence, and run deterministic plan checks. Compare the number of agent interactions with a UI-only path.

### Execution

Deliver a coherent planning workspace with a seeded persona, polished weekly schedule, plan comparison, evidence views, useful failure states, and a dependable demo path.

### Potential impact

Ground the story in the real burden of combining course offerings, requirements, prerequisites, workload, deadlines, personal goals, and scattered institutional guidance.

### Creativity and ambition

Present CourseContext as a context-building decision workspace rather than a chatbot, catalog search box, or calendar clone.

## Seven-day schedule

### Day 1: Product and contracts

- Lock the demo persona and exact user story.
- Choose the stack and hosting target.
- Specify the domain model and WebMCP tool schemas.
- Identify source data and create a small attributable fixture.

### Day 2: Domain vertical slice

- Implement student context, courses, evidence, and plan scenarios.
- Implement deterministic unit, duplicate, schedule, and prerequisite checks.
- Add unit tests for domain operations.

### Day 3: Human workspace

- Build the weekly schedule and course discovery interface.
- Build Library, quick capture, context, evidence, uncertainty, and decision views.
- Support direct human plan edits.

### Day 4: WebMCP

- Register the final read and mutation tools.
- Route tools through the same domain operations as the UI.
- Add receipts, validation, annotations, and structured diagnostics.

### Day 5: Agent loop and evaluation

- Run the complete task in ChatGPT's in-app browser.
- Verify workspace-first search, visible research capture, and bounded saved-view configuration.
- Repair tool descriptions and result shapes.
- Record WebMCP versus UI-only interactions, latency, and failures.

### Day 6: Deployment and polish

- Deploy the public app.
- Test a clean-session judge path.
- Finish repository instructions, license visibility, and submission copy.

### Day 7: Finalization

- Freeze features.
- Run the complete test and browser verification suite.
- Record and edit the under-three-minute narrated demo.
- Upload the public video and complete the Devpost fields.
- Recheck every public URL before submission.

## Required submission artifacts

- Working public application URL.
- Public source repository with visible open-source license.
- Complete setup and run instructions.
- Text explaining WebMCP fit, improved experience, new joint capability, and implementation.
- Public YouTube video under three minutes with audio.

## Submission risks

- Building a generic chat interface instead of a collaborative product.
- Depending on authenticated Stanford systems during judging.
- Presenting scraped or inferred facts as official.
- Exposing too many small tools instead of a coherent semantic surface.
- Spending the final day on features instead of video and verification.
